# Approved GCO architecture

## Ownership and product
GCO main owns the single WPF .NET 10 app, two pages, one game root, session orchestration, combined analysis, managed REDscript Resolver and verified game-only ZIP. CET and GRSP retain their native and standalone manager ownership. G-REDruntime is the optional shared REDscript runtime, not a second generator. See [component contracts](technical/COMPONENT-CONTRACTS.md), [shared runtime](technical/SHARED-NET-RUNTIME.md) and [technical architecture reference](technical/ARCHITECTURE.md). Historical branch names, GRSP-managed Resolver references and automatic Analyze descriptions in older diagrams are superseded by this document.

## Workflow
- Page 1 Direct/MO2: same existing Install -> Start -> Collect -> Continue flow; restore is independently actionable. Current GCO CET preflight checks 0-Engine folder and init.lua presence; CET owner determines injection compatibility. Respect independent supported profiler domains and verified current-session completion; PresentMon is optional evidence, never fabricated. Preserve original bindings.
- Collect seals completed current evidence; Continue waits for required evidence/report and verifies owner restoration; Page 2 ANALYZE is explicit user action. Generate stages current effective source read-only. New Start or explicit Restore discards uncollected owner-defined live output; only successful Collect archives it. Do not clear completed RESULTS.
- MO2 is a deployment/launch/effective-source provider, not a parallel app. VERIFY resolves selected instance/profile and approved elevation; GCO selects correct profile, no user coordination or modlist edit. One owned virtual layer; temporary physical CET ASI exception only when physical ASI is the winning source, exact owner backup/restore. GRSP remains virtual; do not run full CET manager against live MO2 storage. Keep ordinary settings/data mutable. See [MO2 design](integration/MO2-INTEGRATION-DESIGN.md) and [progress ledger](integration/MO2-INTEGRATION-PROGRESS.md) for implementation detail; old feature-branch-only and pre-correction gates are historical.
- Page 2 uses same existing Analyze/Generate and owner exclusions. Optional default-unchecked Hotscenes ENG-only is forwarded to CET's existing CLI. BACK confirms reset; CLOSE after generation resets and exits; no reset during active/recovery work. Publish combined game-only ZIP and external ownership sidecar atomically under generated_optimizations/pass-YYYYMMDD_HHMMSS. In MO2, partition only the final emitted files (after identical framework omission) by verified effective source origin. Existing physical owners and framework updates go to a conditional _DIRECT.zip, virtual owners and genuinely new framework/helper owners stay in MO2. Do not create empty archives; publish both with their own rollback sidecars in the same atomic pass. Existing owners with effective source split between both locations are refused explicitly rather than silently migrating or splitting them. A legitimate virtual winner remains virtual even if a lower physical file is shadowed; do not assume an old overlay's origin from its name. No installer/report/metadata inside ZIP.

## REDscript and CI
GCO's in-repo REDscript Resolver is the only managed REDscript generator. Use the approved ordered generic plan (ten approved families including STABLE_ARRAY_BOUND_V1) then approved semantic rules; actual plan and tests are source of truth for implemented order. The experimental REDscript native location stage and adapters are manual-only, excluded from automatic generation and shipped GCO optional-backend assets; no blanket refusal of existing overlays. CET native location output is independent. Include framework only when accepted rules require it, compile core against vanilla, full generated stack with official SCC 0.5.31 in CI; no runtime compiler redistribution. See [semantic rules](integration/IMPORTANT-FOR-AGENTS-RED-OPTIMIZATIONS.md), [agreed optimizations](integration/REDSCRIPT-RESOLVER-AGREED-OPTIMIZATIONS.md).
Existing .ci/checkpoints/full-gco.txt, redscript.txt, mo2.txt trigger the corresponding verified workflow on allowed branches; select the appropriate scope. Preserve package/native provenance, no version bump or pin change as part of unrelated work.
