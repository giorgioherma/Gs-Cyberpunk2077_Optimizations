# GCO consolidated profiler report — PresentMon native inputs

**Scope:** GCO's collected CET + GRSP + PresentMon evidence, independent of ANALYZE, generator choices and profiler restoration. Does not change standalone CET's or GRSP's CapFrameX compatibility.

## Production contract

- **COLLECT** saves and seals both original native profiler archives and the optional F11-aligned PresentMon CSV. GCO starts reporting after successful COLLECT in a nonblocking task. Report generation failures never undo collection or block CONTINUE/RESTORE or CET generation.
- **Report owner:** `src/GTotalOptimizer.Core/GcoProfilerReportService.cs`. Original owner CLIs are called on hash-verified, disposable copies only. CET reports via source-owner `--report` with the **actual versioned GCO PresentMon chronology**. GRSP reports native function/frame/spike measurements via its original `--report`, without the obsolete CapFrameX frame-sequence code path.
- **Only one shared frame source in GCO:** original `PresentMon/PresentMon.csv` sealed at COLLECT, its real `CPUStartQPC`, `TimeInQPC`, `MsBetweenPresents`, optional `MsCPUBusy`/`MsGPUBusy`, and CET+GRSP F11 QPC/Unix anchors. No CapFrameX schema imitation, renamed CapFrameX JSON or guessed timezone/lag.
- **CET machine handoff** `Reports/CET/CET_Resolver_Input.json` is generated by CET's existing owner with `frameEvidence.provider=PRESENTMON_2_6`, matching the verified owner `CET_Summary.json`. If PresentMon is absent, the report must say `NOT_CAPTURED`; GCO never uses an embedded legacy `FrameTime/` CapFrameX file instead. GCO's separate existing ANALYZE/GENERATOR staging follows this same native provider policy.
- **GRSP timing:** measured `GRSP_Frames.csv` frame Unix times are anchored to CET capture start for shared 50 ms presentation buckets; no fixed frame-index lag fitting. GRSP self-reports retain original extensive per-mod/function/spike/framework evidence. They do not claim fabricated PresentMon frame data.
- **Recorded spike correlation:** CET's source-owned callback spike start offsets remain in CET's F11 clock; REDscript's `GRSP_Spikes.csv` absolute `unix_ms` markers are converted using the **same verified `CetStartUnixMs`** as the GRSP frames/PresentMon. Only top measured owner spikes within overlap appear in the three-track view. A 50 ms bucket with **no native GRSP frame anchored there is `null`/unobserved, not fabricated as 0 ms REDscript work**. Marker coincidence with a PresentMon hitch is never causal attribution. Separate domain work totals are never added, and relative overlay intensities are never called comparable milliseconds or percent CPU.
- **Combined reporting (2026-11-16 digest extension):** `RESULTS/<collected-session>/Reports/GCO_Profiler_Report.html` and `.json` include a side-by-side comparison of CET and GRSP workload owners, CET callback families versus REDscript hot functions, a short Lua GC/heap versus REDscript script-frame health comparison, and ranked PresentMon hitch windows with CET and GRSP 50 ms observations. The **default single combined graph** draws all three timeline series on a common x-axis, each independently normalized to its visible maximum for *timing-pattern comparison only*. The views appear as selectable **Combined timeline** and **Three synchronized tracks** tabs, with Combined selected by default. An explicit **three synchronized tracks** tab shows separate real-millisecond scales and measured CET/REDscript spike markers; clicking a notable window or a profiler spike opens that tab and zooms all three tracks to the same time. The tab switch retains the shared zoom range and supports arrow-key selection. Owners remain linked at `Reports/CET/CET_Report.html` and `Reports/GRSP/GRSP_Report.html` with all their original data.
- **Truth rules:** scripts measure overlapping scopes; CET+REDscript timing is never added as total CPU or treated as proof of frame-time causation. Present-to-present intervals are not displayed latency. PC latency, dropped/FG metadata and unavailable optional fields remain `NOT_CAPTURED`/null. No in-game source files or sealed collection indexes are mutated. Reports are not part of the clean optimizer ZIP.
- **UI:** existing RESULTS folder action unchanged. Completed report path is shown on Page 2; report creation is not an ANALYZE prerequisite. No new page, profiler, monitor, user permission or restoration gate.
