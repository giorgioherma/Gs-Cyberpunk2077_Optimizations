## 1. Verified CET source and successful boundaries

CET reference sources checked on `dev/resolver-profiler-handoff` commit `db904b6a5670ee340ee5b1236c045b5fceecc208`:

| Actual CET mechanism | Exact source and behavior | Portable lesson / limit |
|---|---|---|
| **Source-wide shared native getters** | `SharedProviderCatalog.cs`, `NativeReadReuseSource.cs`, `docs/resolver/NATIVE-READ-REUSE-AUTO-ADOPTION.md`: lexical `Game.GetPlayer()`, `Game.GetQuestsSystem()`, other exact zero-argument facade getters transformed to existing 0-Engine shared providers; named helper retains original `Game.Get…()` fallback. Source shadowing and unexpected return types refuse. Existing helper recognized; compatible partial files composed in stages. | Shared providers + current-source generic adapters, not permanent mod-specific lookup rules. Read-only `Get…` is not assumed pure. CET deliberately refused arbitrary `GetWorldPosition` caching when return type/phase freshness were unknown. |
| **CET StateSignals** | `resolver-runtime/0-Engine/modules/GCETStateSignals.lua`: shares **inVehicle, inCombat, inMenu, district** signals from existing 0-Engine events; no additional per-frame poll. Per-key value, version, generation; duplicate equal values suppressed; `PlayerInvalidated` makes state UNKNOWN and increases generation. Opt-in Watch/Cancel/Pause/Resume. | The key reusable optimization is **one authoritative state producer, multiple cheap consumers**, with explicit UNKNOWN/lifetime and no silently stale answers. |
| **Blackboard reuse** | `docs/experiments/0ENGINE-SHARED-STATE-AUDIT-20261019.md`: 12 PlayerStateMachine key definitions cached once, with user-measured ~95% reduction **in that specific allocation measurement**; 11 GetInt and 1 GetBool per update still executed. It removed redundant **definition lookup**, not necessarily the changing value reads. | Separate immutable field-definition/metadata cache from *current values*. This distinction is critical for REDscript Blackboard/TweakDB/Reflection. |
| **Native location coordination** | `resolver-runtime/0-Engine/modules/GCETNativeLocationHost.lua` + `docs/resolver/research/NATIVE-STATIC-COMBINED-PASS-EXTENSION-2026-10-20.md`: one optional source-compiled static-location registry, one shared 0-Engine **0.10-s event-drain job**, aggregated owner NEAR/FAR transitions; owner callbacks control original work. Static site and exact author near-radius remain distinct (conservative coarse region vs exact interaction). UNKNOWN, stream resync, callback failure or native loss restore original owner behavior. | **Shared coarse spatial signal** can avoid repeated owner-specific proximity/geometry queries, but does not automatically authorize dormancy. Avoid hardcoded locations/mod IDs; dynamically compile live source-defined anchors and prove owner-specific exact fallback. |
| **Pausable frame clients** | `resolver-runtime/0-Engine/modules/GCETFrameListeners.lua`, `docs/0-engine/0-ENGINE-WORKLOAD-SERVICES.md`: opt-in pause/detach of adopted CET onUpdate/onDraw listener at safe boundary. On Resume it may append and change dispatch order. Separately, `GenericUiVisibilityTransform.cs` only hoists visibility gate ahead of draw work; that is an **early return**, not physical detachment. | Distinguish **(a)** no-op body, **(b)** paused owner work, **(c)** removed upstream observer/native marshalling. Never call all three dormancy. REDscript HUD/ink lifecycles are not CET ImGui onDraw callbacks. |
| **Action routing** | Existing 0-Engine finite actions and shared subscription routing, reused by source-gated CET transforms. OnAction origin/wrapped effects and native marshalling may still execute even after downstream suppression. | Reuse G-REDruntime InputHub only if raw action, action type, button state, consumer, ordering, registration and lifecycle can be preserved. Not universal input rewrite. |
| **Time-bounded, optional maintenance** | `GCETWorkQueue.lua` separable work, `GCETPhasePlanner.lua` slack-bounded maintenance, `GCETFrameListeners.lua` adopted callbacks; opt-in and source proven. Scheduler and jobs do not automatically save execution; long indivisible calls cannot be preempted. | Do **not** create generic REDscript work-queue or scheduler pass just to copy infrastructure. Need explicit work granularity, latency and reduction proof. |
| **True active-work stopping** | `docs/phase3/PHASE3-ALLOCATION-CONTROLL.md` + `INSTRUMENTATION-BLUEPRINT.md`: CET records actual job calls, alloc ops/bytes and framework vs owner work. User-confirmed controlled A/B proved selected Dedra, SitAnywhere, CyberTrials jobs at **zero targeted calls/positive allocator requests** in their inactive states; that does NOT prove all native hooks removed. | Generic REDscript should measure **whole omitted work**, not count guard insertions. No broad semantic dormancy adoption without full wake/cleanup proof. |

**CET's fixed generation order remains:** generic 0-Engine → native integration → generic finalization → source-aware semantics; test pristine, partial, completed, source drift, second-pass no-op and original game fallback. For REDscript transfer the *principles* apply, not the exact Lua architecture nor a need to duplicate CET's framework.

## 2026-11-17 — user-provided GCO native player-state-machine archive inspected

User reference: [GCO main test fixture folder](https://github.com/giorgioherma/Gs-Cyberpunk2077_Optimizations/tree/main/tests/G-CETtoNATIVEplayer_state_machine). Verified GitHub tree content: **one** ZIP, \`G-CET_TO_C++_PLAYER_STATE_MACHINE.zip\` (61,931 bytes), with only five archive entries: three directories, \`red4ext/plugins/G-CET-StaticLocations/G-CET.locations\` (9,060-byte **binary anchor manifest**, GCAS header) and \`red4ext/plugins/G-CET-StaticLocations/GCETStaticLocations.dll\` (134,656-byte **native RED4ext plugin**). No C++ source, no REDscript wrapper, and no standalone PlayerStateMachine blackboard reader are packaged in this fixture. The DLL CRC32 \`16cc3d46\` / length matches the same DLL in the user-provided local CET AUTO OPT archive; this proves matching size+CRC, not an audited source build identity.

**Native plugin API confirmed from the corresponding CET packaged binary:** CET RTTI functions \`GCETPlayerApiVersion\`, \`GCETPlayerCapabilities\`, \`GCETPlayerStatus\`, \`GCETPlayerEpoch\`, \`GCETPlayerRevision\`, \`GCETPlayerX/Y/Z\`, \`GCETPlayerVector4\`, \`GCETPlayerVector4Live\`, \`GCETPlayerVector4Valid\`, and \`GCETStaticSubscribe/Poll/State/AnchorAt/Arm/... \`. The PE exports are \`Main\`, \`Query\` and \`Supports\`, not directly exported arbitrary Windows API calls. CET's [typed-vector source contract](https://github.com/giorgioherma/G-CET_Runtime_Profiler/blob/dev/resolver-profiler-handoff/docs/resolver/NATIVE-PLAYER-TYPED-VECTOR-LIVE.md) explicitly uses \`Vector4Live\` for an **on-demand read** and checks \`Vector4Valid\`; frame-cached position and return-value/type compatibility are **not** automatically safe for arbitrary REDscript callers. Need independently verified REDscript RTTI access, lifecycle, exact vector W, game version, session epoch and original getter fallback before making a runtime adapter. **Do not install, duplicate, rebuild or auto-depend on the CET native plugin as a result of this archive inspection.**

**Separate genuine PlayerStateMachine blackboard transform:** CET \`src/G.CETProfiler.Core/Services/BlackboardPsmDefinitionCacheSource.cs\` caches 12 \`GetAllBlackboardDefs().PlayerStateMachine\` **definition keys** once during \`BlackboardCache.Init\` and continues using live \`GetInt\` and \`GetBool\` reads; it does **not** provide a native blackboard value cache. REDscript generic opportunities should recognize repeated immutable definitions across authors independently; never use position DLL capability as proof of blackboard state snapshots. This source implementation, not the ZIP label, is authoritative for the 12-definition optimization.

## 2. Current G-REDruntime (what exists and what is missing)

Verified source `G-REDruntime_Framework/main`, commit `3cf374036bdc0bedb655ef78e117d7696a100055`, manifest `0.6.0-pass6`:

- **Already present:** `StateCache.reds` weak refs for player and ~14 GameInstance services, lazy system lookups; `Runtime.reds` attaches player and marks `PLAYER` dirty; `ContextService.reds` lazily reads combat/mounted vehicle at **0.05 s** intervals; `DirtyFlags.reds` supports global marks/versions and per-consumer `ChangedSince`; `EventBus`, `Scheduler` (one DelaySystem deadline, **0.05 s** floor, missed-tick no-replay), `InputHub` (specific/wildcard input, reused event, 0.10-s device poll), `HookBus`.
- **Not a CET StateSignals equivalent yet:** ContextService reads values lazily; `DirtyFlags.Mark` requires an actual producer. It does **not** automatically subscribe to/source-validate all combat, vehicle, menu and district transitions, nor provide an explicit unified per-state **UNKNOWN + generation** contract. A 50-ms cached combat Bool is not the same as exact value on the original call.
- **Not a native NEAR/FAR equivalent:** no typed REDscript shared static-source anchor coordinator / owner subscription / native event bridge in the current ten framework scripts. CET's Lua RED4ext API cannot simply be assumed callable with the same ABI from REDscript. The known GCO combined SCC compilation of framework+mod source verifies compilation, not an engine-native location contract.
- **Not global immutable-value memoization:** `StateCache` caches *handles*, not changing quest facts, positions, vectors, UI values or arbitrary arrays. `DirtyFlags` is an O(n) search through flag entries; `InputHub` routes are likewise arrays. Creating a new global map can cost more than the reads it eliminates if fan-out is small.
- **Proof-needed lifecycle:** runtime code currently explicitly shows `OnPlayerAttach` and `OnDetach`; source-side proof must establish the full player detach/reload/replacement invalidation paths before authorizing cross-callback persistent values. Do not infer missing lifecycle behavior solely from method names; verify actual game events and source.
- **InputHub semantic limitation:** `InputEvent` only has name/type/consumed; raw `ListenerAction` and original `ListenerActionConsumer` are not in forwarded public event. Replacing wildcard source that needs full button/held/consumer data is unsafe without owner-side API work.

## 3. REDscript generic-first service strategy — ranked to the user's priorities

**Step 1: source-proof a shared state/service provider before adding another framework service.** Do a read-only scan across every current installed `.reds`, joined with capture callsites, to identify concrete common source operations:

1. **G-STATE-READ / G-SYSTEM-HANDLE:** identical `GameInstance`/player handle getters with matching receiver/lifetime; replace only exact proven patterns with existing StateCache provider and original fallback. Distinguish safe weak handles vs volatile request/scene data. Baseline exposure: `GameInstance.GetQuestsSystem` ~633k recorded outgoing edges / ~301 ms exclusive across ~23 owners; `GetPlayer` family ~308k / ~483 ms across ~45 owners. These are *direct cost ceilings*, so demand a cheap broad generic rule; framework dispatch may erase the gain.
2. **G-STATE-SIGNALS:** for source-proven high-cost repeat reads in several authors, add **one owner framework event-backed value+version+UNKNOWN+generation** producer for combat/vehicle/menu/district first, only where authoritative game transitions actually exist. Consumers remain source-local adapters; unrelated properties use original live getter. Audit same-frame changes, teleport, save/load, detach/replacement and optional-mod absence. Do **not** make `ContextService`'s existing lazy 50-ms value an instant-equivalence promise.
3. **G-IMMUTABLE-DEFINITION / TABLE:** share or preconstruct genuinely immutable `CName` names, reflection handles, fixed array membership, descriptor records, blackboard/TweakDB **definitions**, not changing values. First opportunity is source-local repeated literal-provider construction or repeated metadata creation; a cross-owner table is permitted only for identical type, value, equality and no mutable/alias escape. Existing `ACTION_LITERAL_MEMBERSHIP_V1` is one narrow example; first show repeated construction/lookup work from real F11, not just source count. For mutable keyed tables maintain a complete mutator-generated version/index and original fallback; missing writer proof => refuse.

**Step 2: UI/refresh next, using verified state generations.** The CET onDraw lesson is **gate before constructing the UI state**; REDscript equivalent is a source-recognized `ink`/controller update, buff/visibility/animated status effect, widget generation and first-use path. Use `DirtyFlags.ChangedSince` with per-consumer generation **only after every mutator and event is known**. Skip repeated **pure list rebuild**/identical setters, not dynamic timeRemaining/animations/notification effects. The prior F11 family has 75 `UPDATE_REFRESH` owners, ~11.51M outgoing edges / ~12,448.7 ms instrumented exclusive; these rows are heuristic *exposure*, not proven skipped work or callback entry counts. All seven reviewed owners are eligible for this generic.

**Step 3: shared FAR/NEAR spatial publisher.** Follow CET's **coarse filter before exact source semantics**. Make owner G-REDruntime surface an optional typed event/provider **only after** a genuine REDscript-compatible native player/location signal is proven with correct vector type and time/teleport/transition guarantees. Discover static locations from current `.reds` at generation time; no fixed mod list or coordinate/hashes. Many consumers can share one producer and receive different source-derived NEAR/FAR radii. On UNKNOWN, stale epoch, unloaded framework, unsupported dynamic anchor or attach/detach ambiguity, execute the **original source path**. Physical callback/observer dormancy stays a separate higher-risk proof; a generic near/far **cheap prefilter** is a smaller first pass.

**Step 4: merge provably duplicate observers/registrations.** Source-wide detect equivalent listener topic, actual game instance, same engine callback semantics and per-consumer lifecycle. A shared source-owner observer may fan out exact events once (InputHub/EventBus/HookBus) only if registration/ordering/consumption/return semantics are identical and detaching one subscriber cannot remove another's observer. Most existing input wrappers require original raw args; do not blindly route them through `InputEvent`. Where observer identity is not provable, do not coalesce.

**Step 5: transparent data/memo/index reuse.** Prefer lexical same-callback pure common-subexpression reuse and source-immutable local tables, then per-controller generation-indexed collections. Allow a framework-wide table only for measured shared read-only metadata with correct identity/lifetime. Changing arrays with duplicates/first match/ordering/recreation are **not generic constants**.

## 4. What NOT to copy from CET

- **Not** a broad heuristic that `OnUpdate` means frame polling: REDscript `OnUpdate(ResourceEvent)` and native ink updates have different registration and effects. CET's `onDraw` is **Lua/ImGui**, not a REDscript hook.
- **Not** opaque Lua player vector snapshots in REDscript or a global `player position` cache: phase/freshness, Vector4 W, receiver identity and teleport still matter.
- **Not** 0-Engine scheduler frequency defaults transplanted to G-REDruntime: 0.10 s native drain may be appropriate for one source-proven host but is not a general gameplay latency target. REDscript current scheduler min 0.05s and missed-tick semantics can change author behavior.
- **Not** event-driven flags without a complete real producer; a 50 ms poll with version tracking is still polling and can miss intervening transitions.
- **Not** a shared table by mod folder, a permanent semantic author library, arbitrary subscription removal, or a duplicate GCO-owned framework.
- **Not** a new profiler just to prove something already visible in actual F11 CSVs; new capture/instrumentation only if a specific high-value pass is blocked by a measurable missing fact.
- **Not** an assertion of no mod-specific work: the framework enables broad generic **infrastructure**, while author-specific wake/quest/action rules still require targeted R7 proof for uncovered remainder.

## 5. Small, testable next generic passes

**First code exploration (not yet authorized):** `G-SharedResolvedHandle` — exact `GameInstance.GetXSystem(game)` patterns with proven same game/epoch/type, using StateCache only if repeated call bypass wins after framework-entry overhead. Implement a source-only scanner and measured runtime exposure ledger first. Original getter fallback, partial/complete state, drift and SCC 0.5.31 are mandatory. **No performance claim until A/B.**

**Second:** `G-StaticDefinitionOnce` — pure, fixed definitions or immutable constant tables previously reconstructed every callback; contrast CET's verified blackboard *definition* cache with fresh per-call values. Rank independently across mods; source-local reuse may win without framework changes. Strict alias, mutation and initialization proof; do not build global table service until repeated cross-owner demand is proven.

**Third (owner API gate first):** `G-StateSignalSubscribe` — state transition producer and consumer contract with unknown/lifetime; the service must be implemented in G-REDruntime repo, not GCO, after source proof. Then GCO generates only source-admitted consumers.

**Fourth:** `G-CoarseNearFar` — optional shared player region events (or cheap pure AABB outside check) with exact original fallback; no automatic physical dormancy. Typed REDscript native bridge and lifespan evidence required before framework service.

**Fifth:** `G-UiDirtySubtree` — complete input-to-widget generation proof to skip an entire redraw/rebuild; source admission not tied to seven reviewed owners.

These steps are not a directive to build all five. At each step demand actual F11 call volume, measured exclusive cost, an observed **avoidable** fraction or a mathematical/source proof of it, and cross-owner matching. If one family is low benefit or unsafe, mark refused and move on.
